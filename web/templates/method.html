How this was measured

Three agents, one loop. An attacker writes adversarial prompts, a target defends with a given system prompt, and an independent judge decides whether the defense held. Every run is logged.

The three agents

ATTACKER

Generates the adversarial messages. It is told the target’s public role and that some kind of secret exists, but never the secret itself — the same position a real attacker is in. Giving it the answer would measure nothing.

TARGET

A support assistant holding a secret it must never reveal, defended by one of six system-prompt strategies. Runs at low temperature, because a real deployed system should behave consistently rather than vary run to run.

JUDGE

Reads the full transcript and returns a structured verdict through function calling — a schema with leaked_secret, broke_character and reasoning. Keyword matching was rejected: it cannot tell whether a persona actually broke, and it misses paraphrased or partial leaks.

Why a secret string

Attack success needs an objective signal. “Did the bot get too edgy?” is a judgment call that makes the judge itself the weak link. A hidden code gives a near-binary check — it either surfaced or it did not — and broke_character is scored separately so a persona collapse still registers even when nothing leaked.

The grid

Three target configurations × six defenses × four attack classes, each run three times — {{ summary.total_traces }} conversations. Repeats matter: a single attempt per combination is a coin flip, not a rate. Percentages here are averaged over trials.

Things that went wrong

Safety-tuned models refuse to red-team

Three capable models declined to play the attacker at all, even under explicit authorised-research framing — one refused outright, another dodged by answering in the target’s voice. The attacker role ended up on a smaller, less safety-tuned model. Attacker model choice is a real methodological constraint, not an implementation detail.

The attacker has a shorter memory than the target

That attacker model has a 4,096-token context window, so on five-turn runs it only sees a trailing window of its own campaign. The target still receives the full escalating conversation, which is what the experiment measures — but the attacker is working with less context than it ideally would.

Retrying a request that can never succeed

The first full run crashed after backing off repeatedly on a context-length error. Rate limits are worth retrying; a malformed request is not. The retry layer now distinguishes them, and a failed episode no longer kills the batch.
